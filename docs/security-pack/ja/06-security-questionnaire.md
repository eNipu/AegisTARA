# 6. セキュリティ質問票への回答

## 6.1 本章の使い方

本章は、概念実証の前に、買い手のセキュリティチームがよく尋ねる質問への、すぐに使える回答です。回答をお客様自身の書式にコピーし、詳しい内容を読む場所として参照先を示してください。

- 回答は、出荷された状態の製品について述べています。各回答は、1 章から 5 章のいずれかの節、または参照先の欄に挙げたファイルに基づいています。
- `はい`: 製品は、構築された状態でそれを行います。
- `いいえ`: 製品は、それを行いません。
- `一部`: 回答が、その限界を説明します。
- `お客様`: お客様が自社の環境でこれを行います。お客様が製品をホストするためです。
- `計画中`: 決定されていますが、構築されていません。
- `ベンダー`: 製品ではなく、ベンダーの組織についての質問です。ベンダーは、お客様ごとの契約書類の中で回答します。

## 6.3 アクセス制御

| ID | 質問 | 状況 | 回答 | 参照先 |
|---|---|---|---|---|
| Q-09 | シングルサインオンに対応していますか。 | はい | 会社ログインは、システムブラウザーでの PKCE 付きの OpenID Connect を使い、トークンはデバイスに結び付けられます。これが、製品を本番で運用する方法です。 | 3.2 |
| Q-10 | 多要素ログインに対応していますか。 | 一部 | 製品自体には、多要素ログインがありません。会社ログインでは、お客様の ID プロバイダーが提供します。パスワードログインにはありません。 | 3.2, 3.3 |
| Q-11 | パスワードのポリシーはどうなっていますか。 | はい | パスワードログインでは、10 文字以上、256 バイト以下で、空白だけでなく、ユーザー名と同じでもありません。文字種の組み合わせのルールはありません。 | 3.3 |
| Q-12 | パスワードの推測に対する保護はありますか。 | はい | パスワードログインは、ユーザー名ごとに 5 回失敗すると待ち時間が長くなり、15 分まで倍々に増えます。また、20 回失敗したアドレスは速度を落とされます。未知の名前でも、既知の名前と同じ時間がかかります。 | 3.3 |
| Q-13 | セッションのタイムアウトはどうなっていますか。 | 一部 | パスワードのセッションは、既定でログインの 12 時間後に終わります (1 から 720 時間)。使用状況は関係ありません。別個のアイドルタイムアウトはありません。 | 3.4 |
| Q-14 | アクセスはロールに基づいていますか。 | はい | すべての呼び出しが、プロジェクトでのユーザーのロールに照らして確認されます。組み込みのロールは 6 つで、編集はできません。 | 3.5, 3.8 |
| Q-15 | アクセスはプロジェクトごとに制限されますか。 | はい | メンバーシップはプロジェクトごとです。メンバーシップのないプロジェクトは、管理者でないユーザーには見えません。グループのメンバーシップは構築されていません。 | 3.5 |
| Q-16 | 管理者の職務は分離されていますか。 | 一部 | プロジェクトのロールには、サーバー管理を与えるものはありません。サーバー管理者は、すべてのプロジェクトのすべての権限を持ち、最後の管理者は削除できません。 | 3.5 |
| Q-17 | 退職者はどのように除外しますか。 | 一部 | パスワードログインでは、管理者がアカウントを無効にするか削除すると、そのセッションが終わります。会社ログインでは、お客様が自社の ID プロバイダーでその人を削除します。どちらの場合も、メンバーシップの行は、誰かが削除するまで残ります。 | 3.4, 5.2, 5.4 |
| Q-18 | 共有アカウントや既定のアカウントはありますか。 | 一部 | 組み込みの既定のパスワードはありません。最初の管理者のパスワードはお客様が設定し、サーバーはユーザーが 1 人もいない間だけそれを使います。開発用ログインはオフでなければならず、リリースチェックリストがそれを求めています。 | 2.3, 3.2 |

## 6.4 暗号

| ID | 質問 | 状況 | 回答 | 参照先 |
|---|---|---|---|---|
| Q-19 | 通信中のデータは暗号化されますか。 | 一部 | デスクトップアプリは、サーバーのアドレスへ TLS を使います。サーバー自体は平文の HTTP で通信するため、お客様のプロキシが TLS を終端し、平文のポートを他のネットワークから遠ざけます。 | 1.5, 2.2 |
| Q-20 | どの TLS バージョンを使いますか。 | はい | アプリとデータベース接続は、TLS 1.2 と 1.3 を使い、証明書を検査します。データベースへの TLS は既定ではオフで、`AEGIS_DB_TLS` でオンにします。 | 2.2 |
| Q-21 | 保存データは暗号化されますか。 | お客様 | 製品は、保存データを自分では暗号化しません。ディスクまたはデータベースの暗号化は、お客様の責任です。 | 2.5 |
| Q-22 | パスワードはどのように保存されますか。 | はい | パスワードごとにランダムなソルトを付けた Argon2id のハッシュとしてのみ保存されます。セッショントークンは、SHA-256 のハッシュとしてのみ保存されます。 | 2.2, 2.5 |
| Q-23 | 鍵はどのように管理されますか。 | 一部 | ベンダーは、ライセンスと更新の署名鍵をオフラインで保管します。お客様は、プロキシの証明書、データベースのパスワード、ID プロバイダーの設定を保管します。 | 2.3 |
| Q-24 | 独自に設計したアルゴリズムを使っていますか。 | いいえ | 署名、TLS、乱数は、オープンソースのライブラリーから来ています。製品には、独自のアルゴリズムはありません。 | 2.1, 2.6 |
| Q-25 | 暗号は FIPS 140 の検証を受けていますか。 | いいえ | 暗号のコードは検証されておらず、本資料は認証を主張しません。 | 2.6 |

## 6.5 ログと監視

| ID | 質問 | 状況 | 回答 | 参照先 |
|---|---|---|---|---|
| Q-26 | セキュリティイベントは記録されますか。 | はい | サーバーは、ログイン、ログアウト、パスワードとユーザーの変更、エクスポート、ベースライン、プロジェクトの削除、メンバーシップの変更のイベントログを保持します。プロジェクトへのすべての変更も、誰が行ったかとともに保持されます。 | 4.2, 4.3 |
| Q-27 | ログのエントリーには何が入りますか。 | はい | 時刻、実行者、種類、対象、短い詳細です。パスワードやセッショントークンは入りません。ログインに失敗した場合は、ユーザー名が入力されたまま保持されます。 | 4.3 |
| Q-28 | ログは変更できますか。 | 一部 | どちらのログも SHA-256 のハッシュチェーンであるため、サーバーを介さない変更は見つかります。テーブル全体を書き換えるデータベース管理者は、お客様が先頭のハッシュを別の場所に保管していない限り、この検証を破れます。 | 4.4 |
| Q-29 | ログはどのくらいの期間保持されますか。 | はい | イベントログは、既定で 365 日と 1,000,000 件を保持し、どちらの上限も変更できます。プロジェクトの履歴は削減されません。 | 4.5 |
| Q-30 | ログを当社の SIEM に送れますか。 | 一部 | 組み込みの転送機能はありません。お客様は、プロセスログを標準出力から収集し、イベントテーブルを自分のツールで読みます。 | 4.7 |
| Q-31 | ログの時刻はどこから来ますか。 | お客様 | UTC のサーバー自身の時計からです。その時計を正しく保つことは、お客様の責任です。 | 4.6 |
