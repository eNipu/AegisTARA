# 5. 個人データの取り扱い (GDPR と個人情報保護法)

## 5.1 範囲と役割

本章は、製品が個人データを何のために保存し、どう扱うかを説明します。本章は法的助言ではありません。

- お客様がサーバーを運用し、誰が使うかを決めます。お客様は、EU一般データ保護規則（GDPR）では管理者にあたり、日本の個人情報の保護に関する法律（個人情報保護法）では個人情報取扱事業者にあたります。
- ベンダーは、製品を通じて個人データを受け取りません。ベンダーには何も送られず、テレメトリーもなく、ライセンスサーバーもありません (1 章)。
- ベンダーが個人データを扱うのは、お客様がサポートのためにそれを渡した場合だけです。それは契約で扱われ、製品では扱われません。
- 製品は、人ではなく、車両と部品を分析するために作られています。プロジェクトの内容には、個人データが含まれないはずです。自由記述欄には、ユーザーが入力したものが入ります。そのため、そこに個人データを入れないことは`お客様`が行います。
- 製品自体が保持する個人データは、ユーザー名、いくつかの関連する事実 (時刻、コンピューター名、メモリー内に保持されるネットワークアドレス)、および各変更を行った人の名前です。5.2 がそのすべてを挙げています。

## 5.3 保存期間と削除

| データ | 保持期間 | 削除するもの |
|---|---|---|
| アカウント、パスワード、セッション | 削除されるまで | 管理者がアカウントを削除します。セッションはアカウントとともに消えます |
| セッション | 有効期限が切れるまで | 有効期限切れ、ログアウト、または管理者 |
| イベントログ | 保存期間 (4.5) | 1 時間ごとの削減。古いものから |
| 操作履歴、ベースライン、図 | プロジェクトが存在する間 | プロジェクトの削除 |
| メンバーシップ | 削除されるまで | プロジェクトオーナーまたは管理者 |
| デスクトップの設定とキーチェーン | ユーザーのコンピューター上 | ユーザー |

限界をはっきり述べます。操作履歴とイベントログはハッシュチェーンです (4 章)。その中にあるユーザー名は、チェーンを壊さずに 1 エントリーずつ変更したり削除したりすることはできません。そのため、次のようになります。

- 削除されたアカウントの名前は、その人が編集したすべてのプロジェクトの操作履歴に、そのプロジェクトが削除されるまで残ります。
- イベントログには、保存期間の処理がそれらのイベントを削除するまで残ります。
- その名前を含むメンバーシップの行は、誰かが削除するまで残ります。

お客様にできること:

- 会社ログインを使います。保存される識別子は、ID プロバイダーがトークンに入れるサブジェクトになります。その形式を製品が選ぶことはありません。多くのプロバイダーは不透明な ID を使い、メールアドレスを使うものもあるため、`お客様`が自分のプロバイダーが送るものを確認します。不透明な ID であれば、保存される識別子は個人の名前ではありません。
- パスワードログインでは、個人名の代わりに、ロール名または仮名のユーザー名を使います。表示名には引き続き実名を表示できます。表示名は履歴には保存されず、アカウントにだけ保存されます。
- `AEGIS_EVENT_RETENTION_DAYS` を、お客様自身の方針に合わせて設定します。

## 5.4 本人の権利

製品の現状で、お客様が請求にどう応じるかを示します。

| 権利 | 方法 |
|---|---|
| アクセス | 管理者は、管理ページでアカウント、セッション、イベントを確認できます。プロジェクトの履歴には、誰が何を変更したかが示されます。お客様は、自分のデータベースのテーブルを読むこともできます |
| 訂正 | 管理者が表示名を変更します。ユーザー名は、作成後に変更できません。代わりに新しいアカウントを作成します |
| 削除 | 管理者がアカウントを削除すると、そのセッションは終了します。履歴とイベントログには、5.3 の限界が当てはまります |
| 制限 | 管理者がアカウントを無効にします。そのセッションは終了し、ログインできなくなります |
| ポータビリティ | 製品の機能ではありません。データは、お客様自身のデータベースにあります |
| 異議 | 製品の機能ではありません。誰にアカウントを持たせるかは、お客様が決めます |

会社ログインの場合、製品の中にアカウントはありません。お客様は、自社の ID プロバイダーでその人を訂正または削除し、製品内ではメンバーシップの行を削除します。

## 5.5 GDPR との対応

| 条 | 製品がお客様をどう支えるか | 状況 |
|---|---|---|
| 5 (データの最小化、保存の制限) | 製品が保持する個人の情報は少ないです (5.2)。イベントログには定められた保存期間があります。履歴は、プロジェクトの存続期間中保持されます | 保存期間と、自由記述に何を入れるかは、`お客様`が決めます |
| 25 (データ保護バイデザインとバイデフォルト) | テレメトリーなし、ベンダーのサーバーなし、ネットワークアドレスは保存されない、パスワードとセッショントークンはハッシュ化、ログの文面には上限あり | 保存期間とログイン方法は、`お客様`が設定します |
| 30 (処理の記録) | 5.2 の一覧が、その元になります | `お客様`が記録を保持します |
| 32 (セキュリティ) | 2 章、3 章、4 章を参照: 暗号化、ログイン、ロール、ハッシュチェーンのログ | デプロイ、データベース、バックアップは、`お客様`が運用します |
| 15 から 17 (アクセス、訂正、削除) | 5.4 と、5.3 の限界を参照 | `お客様`が本人に回答します |
| 33 と 34 (侵害) | イベントログとプロジェクトの履歴が、何がいつ起きたかを示します。報告された脆弱性に対するベンダーの対応は、`SECURITY.md` にあります | 通知をするかどうかの判断と通知は、`お客様`が行います |
| 44 (移転) | 製品は、お客様のデプロイの外へデータを送りません | サーバーとデータベースをどこで動かすかは、`お客様`が選びます |
| 28 (処理者) | ベンダーは処理者ではありません。ただし、お客様がサポート用のデータを渡した場合を除きます | 渡す場合は、`お客様`が契約を結びます |

## 5.6 個人情報保護法との対応

法律の条文ではなく、義務ごとに説明します。

| 義務 | 製品がお客様をどう支えるか | 状況 |
|---|---|---|
| 利用目的の特定 | 利用目的は、一覧 (5.2) にあります | `お客様`が本人にそれを示します |
| 個人データの安全管理措置 | 2 章、3 章、4 章を参照 | `お客様`がデプロイを運用します |
| 従業者の監督と委託先の監督 | ロールとイベントログが、誰が何をしたかを示します (3 章と 4 章) | `お客様` |
| 第三者提供の制限 | 製品は、いかなる第三者にも何も提供しません | `お客様`自身がエクスポートするものについては、`お客様` |
| 外国にある第三者への提供 | 製品は、データを外へ送りません。サーバーをどこで動かすかは、お客様の選択です | `お客様` |
| 本人からの請求: 開示・訂正・利用停止等の請求 | 5.4 を参照 | `お客様`が本人に回答します |
| 漏えい等の報告 | イベントログは、何が起きたかを調べる助けになります。報告された脆弱性に対するベンダーの対応は、`SECURITY.md` にあります | `お客様`が、当局と本人に報告します |
