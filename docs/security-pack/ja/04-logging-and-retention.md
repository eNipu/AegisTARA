# 4. ログと保存期間

## 4.1 概要

サーバーは、起きたことの記録を 2 種類保持します。イベントログには、セキュリティと管理のイベントが入ります。ログイン、エクスポート、ユーザーの変更、プロジェクトの削除です。各プロジェクトの操作履歴には、プロジェクトへのすべての変更が、誰がいつ行ったかとともに入ります。どちらも SHA-256 で連鎖しているため、サーバーを介さずに行われた変更は見つけられます。イベントログは期間と大きさで削減されます。操作履歴は削減されません。サーバーは通常のプロセスログも標準出力に書き出し、お客様のプラットフォームがそれを収集します。サーバーが自分でログをどこかへ送ることはありません。イベントログには、パスワード欄もセッショントークンも保存されません。ログインに失敗したときは、入力されたユーザー名が入力されたままの形で記録されます (4.3)。

## 4.2 ログの種類

| ID | ログ | 記録する内容 | 保存場所 | 読める人 | 保持期間 |
|---|---|---|---|---|---|
| LG-01 | イベントログ | セキュリティと管理のイベント (4.3)。それぞれに時刻、実行者、種類、対象、詳細が付きます | PostgreSQL のテーブル `aegis_event`。データベースがない場合 (メモリのみ) は、サーバーのメモリ内 | アプリ内のサーバー管理者。`お客様`は自分のデータベースツールでテーブルを読みます | 既定で 365 日と 1,000,000 件 (4.5) |
| LG-02 | プロジェクト操作履歴 | プロジェクトへのすべての変更。連番、時刻、実行者、変更内容、チェーンのハッシュです | PostgreSQL のテーブル `aegis_project_op`。スタンドアロンモードでは、プロジェクトフォルダー内のファイル | プロジェクトを読めるユーザーは、誰が何を変更したかを見られます。`お客様`は自分のツールでテーブルを読みます | プロジェクトが存在する間。削減されません |
| LG-03 | サーバープロセスログ | 起動と停止、ライセンスとログインのモード、データベース接続、マイグレーション、エラーと警告、拒否されたリクエスト (エラーの文面で、トークンは含みません)、エラー行内のプロジェクト ID | サーバーの標準出力。`お客様`が自分のプラットフォームで収集します | `お客様` | `お客様`が決めます |
| LG-04 | デスクトップアプリ | ウィンドウ、キーチェーン、保存された設定、同期についての警告とエラー。アプリはログファイルを書きません | アプリのプロセスの標準エラー出力。アプリはこれをどこにも保存しません | ターミナルからアプリを起動した人 | 保存されません |

現在のコードで、プロセスログに入るもの:

- パスワードとトークンは書き込まれません。
- ネットワークアドレスは書き込まれません。
- ユーザー名が現れるのは次の 2 つの場合だけです。起動時のライセンスのお客様名 (ライセンスを所有する会社) と、イベントログなしで構築されたサーバー (テストと組み込みのみ) で、イベントテーブルの代わりに各イベントがプロセスログに書かれる場合です。
- プロジェクトは、エラー行に ID で現れます。スタンドアロンのプロジェクトフォルダーをインポートするコマンドは、プロジェクト名も書き込みます。
- `RUST_LOG` 変数がレベルを決めます。既定は `info` です。

## 4.3 イベントログの内容

各イベントには 5 つの欄があります。時刻、実行者、種類、対象、短い詳細です。実行者はユーザー名です。会社ログインの場合は、ID プロバイダーからのサブジェクトです。ログインに失敗した場合、実行者は入力されたユーザー名です。対象は、ユーザー名、プロジェクト ID、または空です。イベントログには、パスワード欄もトークンも保存されません。ログインに失敗した場合、ユーザー名として入力された文字列は、入力されたまま記録されます。名前欄に誤って入力されたパスワードは、保存期間によって削除されるまで残ります。テキスト欄は、制御文字が取り除かれ、256 文字で切られます。

| 保存される種類 | 意味 |
|---|---|
| `login_ok` | パスワードログインが成功しました。詳細はアプリの名前です。会社ログインはこのイベントを書きません。ログインは ID プロバイダーで行われるためです |
| `login_failed` | パスワードログインが失敗しました。名前またはパスワードの誤り、無効なユーザー、試行回数の超過、無効な名前、パスワードログインがオフ、のいずれかです。分かっている場合は、詳細にその理由が入ります |
| `logout` | ユーザーがログアウトしました |
| `password_changed` | ユーザーが自分のパスワードを変更しました |
| `user_created` | 管理者がユーザーを作成しました。管理者の場合、詳細は `admin` です |
| `user_updated` | 管理者がユーザーを変更しました。詳細には、変更した内容 (表示名、管理者フラグ、無効フラグ、パスワード) が並びます |
| `user_deleted` | 管理者がユーザーを削除しました |
| `export` | ユーザーがレポートまたは表をエクスポートしました。対象はプロジェクト ID、詳細はエクスポートの種類です |
| `project_deleted` | プロジェクトが削除されました。対象はプロジェクト ID です |
| `baseline_created` | ベースライン (固定されたバージョン) が作成されました。対象はプロジェクト ID、詳細はベースライン ID です |
| `password_login_changed` | 管理者がパスワードログインをオンまたはオフにしました |
| `session_revoked` | 管理者がユーザーのセッションを終了しました |
| `events_trimmed` | 保存期間の処理が古いイベントを削除しました (4.4、4.5) |
| `membership_changed` | プロジェクトのメンバーシップが追加されたか、そのロールが変更されました。詳細はメンバーとロールです |
| `membership_removed` | プロジェクトのメンバーシップが削除されました |

## 4.4 完全性

- イベントログと各プロジェクトの操作履歴は、SHA-256 のハッシュチェーンです。各エントリーは直前のエントリーのハッシュを持つため、変更、削除、挿入されたエントリーがあると、その位置からチェーンが壊れます。
- サーバー管理者は、アプリからチェーンを検証できます。検証は、チェーンが無傷かどうか、最初に壊れた位置、先頭のハッシュを報告します。リリースチェックリストは、前のリリースで使われたデータベースでこの検証が通ることを求めています。
- 保存期間の処理が古いイベントを削除すると、サーバーは削除した件数を添えた `events_trimmed` イベントを書きます。そのため、ログの欠落は見えるままで、チェーンは、残っている最も古いイベントから途切れません。
- チェーンが証明すること: 誰かがサーバーを介さずにデータベースを変更し、チェーンを再計算しなかったことです。
- チェーンが証明しないこと: テーブル全体を書き換え、すべてのハッシュを再計算し、保存されているチェーンの先頭を置き換えられるデータベース管理者は、この検証を破れます。先頭は同じデータベースに保存されています。これを防ぐには、`お客様`が、検証で表示される先頭のハッシュを、データベース管理者が書き込めないシステムにコピーします。

## 4.5 保存期間

| データ | ルール |
|---|---|
| イベントログ | `AEGIS_EVENT_RETENTION_DAYS` より古いイベントは削除されます (既定 365、指定できる範囲は 1 から 3650)。`AEGIS_EVENT_MAX_ROWS` を超える分は、古いイベントから削除されます (既定 1,000,000、指定できる範囲は 1000 から 100,000,000)。どちらもサーバーの起動時に実行され、その後は 1 時間ごとに実行されます。既定値では、テーブルは最大でおよそ 150 MB です |
| プロジェクト操作履歴 | 削減されません。プロジェクトが存在する間は残ります |
| セッション | 有効期限が切れたとき、およびログアウト、無効化、パスワード変更、ユーザー削除のときに削除されます (3 章) |
| 削除されたプロジェクト | その操作、ベースライン、図は、1 つのトランザクションで削除されます |

- 法的な保持期間がより長い場合: 保存期間を延ばすか、削減される前にテーブルをコピーして取り出します (`お客様`)。
- 削減されたイベントをファイルへアーカイブエクスポートする機能は、構築されていません。決定記録には、後回しとして挙げられています。要件にはその名前がないため、`計画中`ではありません。

## 4.6 時刻

タイムスタンプは、サーバー自身の時計によるもので、Unix エポックからのミリ秒 (UTC) です。サーバーの時計が間違っていると、2 つのログの時刻も間違います。時計を正しく保つことは`お客様`が行います。

## 4.7 SIEM へのログ送信

- プロセスログは標準出力へ出ます。お客様の収集ツールのためです。
- イベントログは PostgreSQL のテーブルです。`お客様`は、自分のツールで読めます。たとえば、SIEM へ定期的にクエリーを実行します。
- 組み込みの転送機能 (syslog または webhook) は構築されておらず、それを求める要件もありません。
