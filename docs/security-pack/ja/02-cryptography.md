# 2. 暗号

## 2.1 概要

製品は、オープンソースライブラリの標準的なアルゴリズムを使います。TLS は rustls から、署名と乱数は ring から来ます。パスワードのハッシュ化には Argon2id を、ハッシュチェーンには SHA-256 を使い、どちらもよく知られたオープンソースのクレートによるものです。製品独自のアルゴリズムはありません。デスクトップアプリと PostgreSQL への TLS は、バージョン 1.2 と 1.3 およびオペレーティングシステムのトラストストアを使います。製品自体は保存データを暗号化しません。それはお客様のディスクまたはデータベースの暗号化が担います (`お客様`)。暗号のコードは FIPS 140 の認証を受けておらず、本資料は認証を主張しません。

## 2.3 鍵管理

ベンダーの鍵:

- ライセンスの秘密鍵と更新の秘密鍵は、オフラインで保管します。リポジトリや、プルリクエストをビルドする CI のシークレットには置きません。
- 更新の鍵はライセンスの鍵とは別の鍵で、保持する人数はより少なくなっています。
- ビルドは、組み込まれた公開鍵だけを受け入れます。鍵のないビルドは、どのライセンスも受け入れません。ライセンスは自分の鍵を名指しするので、古いライセンスを壊さずに鍵を交換できます。

お客様の鍵と秘密情報 (`お客様`):

- プロキシにある TLS 証明書とその秘密鍵。
- データベースのパスワード。プライベート認証局の場合は CA ファイルも含みます。
- 会社ログインのための、ID プロバイダーのクライアント登録。

サーバーの設定にある秘密情報について: 最初の管理者のパスワードは、ユーザーテーブルが空の間だけ使われます。その後、サーバーはそれを無視します。製品がメモリ上に保持する秘密情報 (パスワード、PKCE のベリファイアー、クライアントシークレット) は、不要になった時点で上書きされます。

## 2.4 乱数

セッショントークン、ソルト、DPoP のデバイス鍵は、ring を通じてオペレーティングシステムの乱数生成器を使います。製品独自の乱数生成器はありません。

## 2.5 保存データ

- 製品は、プロジェクトを PostgreSQL またはプロジェクトフォルダーに保存します。製品自体は暗号化しません。ディスクまたはデータベースの暗号化は`お客様`です。
- パスワードは、Argon2id のハッシュとしてだけ保存されます。
- セッショントークンは、SHA-256 のハッシュとしてだけ保存されます。
- ソースコードで AES、ChaCha、「encrypt」を検索しましたが、保存データを暗号化するコードは見つかりませんでした。該当したのは、TLS の設定についての文章と、RSA 鍵についてのコメントだけです。

## 2.6 使っていないもの

- 独自開発のアルゴリズムはありません。署名、TLS、乱数は ring と rustls から来ます。
- 製品自身のコードに MD5 や SHA-1 はありません。ソースコードを検索しましたが、見つかりませんでした。PostgreSQL のクライアントライブラリには、古い MD5 のデータベースパスワード方式のコードが含まれています。製品は、それを自身の目的には使いません。`お客様`は、データベースを SCRAM のパスワードログインに設定してください。
- 暗号モジュールは FIPS 140 の認証を受けていません。
