## Goal
Slices 205a and 205b added the generic element store on `Project` (misuse cases, visual ID
`MU`) with `AddElement`, `RenameElement` and `RemoveElement`. This slice adds extra
attributes (decision D34): a pack will declare attributes such as a cybersecurity assurance
level on an element kind, and the values live on the element. One new op,
`SetElementAttribute`, sets or clears one value, with an exact inverse, and goes to the op
log. Packs cannot declare attributes yet (job 176), so the model checks syntax only.

2. **`op.rs`:** add, after `RemoveElement`,
   ```rust

   SetElementAttribute { id: ElementId, key: Arc<str>, value: Option<AttrValue>, provenance: Provenance },
   ```
   Inverse: the same op with the old value (`None` if it was not set) and the element's old provenance. Clearing a key that is not set is allowed and its inverse is the same clear. Add the row to the inverse table and the `Some` arms of `provenance()` and `with_provenance()`.
3. **Checks, in this order, with new `ModelError` variants** (doc and `#[error]` text name only the element ID and the cap, never a key or value):
   - `UnknownElement(id)` if the element is not live;
   - `InvalidAttributeKey { element: ElementId }` if `!is_key(key)`;
   - `InvalidAttributeValue { element: ElementId }` if `value` is `Some(v)` and `!is_attribute_value(v)`;
   - `TooManyAttributes { element: ElementId, max: usize }` if the key is new, `value` is `Some`, and the element already has `MAX_ELEMENT_ATTRIBUTES`;
   - then the provenance check `validate` already runs for every op with provenance.
4. **Removal guard:** `RemoveElement` is now refused with `ElementHasAttributes { element: ElementId, count: usize }` while the element has any attribute (checked after `UnknownElement`). Its inverse stays a plain `AddElement`, so undo is exact. Update the `RemoveElement` doc.
