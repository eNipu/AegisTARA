## Facts already established (do not re-research)
- Versions: `gpui-component 0.9.1` is the newest on crates.io. It uses GPUI through the crates.io snapshot package `gpui-pre =0.3.12` (Zed rev d2a4fb6, Apache-2.0), renamed to `gpui`. Plain `gpui` on crates.io (0.2.2) is not what gpui-component uses; do not depend on it.
- In this GPUI, `gpui::Application` has no desktop platform of its own, only `Application::with_platform(..)`. The desktop platform is the separate crate `gpui-pre-platform =0.3.12` (library name `gpui_platform`, Apache-2.0). Start the app with `gpui_platform::application().run(|cx| ...)` (source: `~/.cargo/registry/src/*/gpui-pre-platform-0.3.12/src/gpui_platform.rs` lines 16-18).
- Feature `runtime_shaders` on `gpui-pre-platform` compiles Metal shaders at run time, so the build does not need Xcode's `metal` compiler. `font-kit` is the macOS text backend that gpui-kit (upstream's facade) also turns on.
- Worktree trap: the worktree sits inside the main checkout, so without its own `[workspace]` table Cargo walks up to the main checkout's root `Cargo.toml` and refuses to build. The spike manifest must keep an empty `[workspace]` table.
- gpui-component 0.9.1 API (it differs from older tutorials; there is no `DockItem`, and the crate ships no `examples/` folder):
  - `gpui_component::init(cx)` once at start; `gpui_component::Root::new(view, window, cx)` is the window root (a re-export of `gpui_base::Root`).
  - Dock area: `let (area, _skin) = gpui_component::dock::DockSkin::dock_area("shell", None, window, cx);` (`gpui-component-0.9.1/src/dock/mod.rs` lines 189-205). Keep the returned `Rc<DockSkin>` alive in the `Shell` struct.
  - Layout: `gpui_component::dock::DockLayout::{h_split(), v_split(), tabs()}`, `.child(layout, Some(px(..)))`, `.panel_view(panel_handle(entity), cx)` (`gpui-base-0.9.1/src/dock/layout/builder.rs` lines 41-110). Install with `area.update(cx, |a, cx| { a.set_center(layout, window, cx); a.set_dock(DockPlacement::Left, layout, window, cx); ... })` (`gpui-base-0.9.1/src/dock/dock_area.rs` lines 232-260).
  - A panel is wrapped with `gpui_component::dock::panel_handle(entity)` (`gpui-component-0.9.1/src/dock/panel.rs` line 325), otherwise its title is not drawn. A panel type implements `gpui_component::dock::BasePanel` (the `gpui_base` panel trait, `panel_name`), `gpui_component::dock::Panel` (`title`), `EventEmitter<PanelEvent>`, `Focusable` and `Render`. Import these through `gpui_component::dock`, not from `gpui_base` (it is not a direct dependency).
  - Multi-line text: `gpui_component::input::TextareaState` rendered with `gpui_component::input::Textarea::new(&state)` (`gpui-component-0.9.1/src/input/textarea.rs` line 70), or `EditorState` with `Editor` (code editor with line numbers, documented as fine up to about 50K lines; `#[doc(hidden)]` but public). `InputState` is single-line only. Prefer `EditorState`/`Editor`; fall back to `TextareaState` if it does not build, and say which in build.md.
