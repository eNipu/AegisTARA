## Goal
After this slice the vendor can run one script, `scripts/offline-bundle.sh`, and get `aegistara-<release>-offline.tar` plus `aegistara-<release>-offline.tar.sha256`: one signed archive for an air-gapped customer site, holding the desktop installers, the release's signed update manifest and, optionally, the server container images. A test script proves a customer can verify it with OpenSSL 3 and `sha256sum` alone, and the CI `check` job runs that test. The library code exists already (slice 100a, module `aegis_license::bundle`).

What 100a provides (in `crates/aegis-license/src/bundle.rs`, read it before you start):
- `SUMS_FILE = "SHA256SUMS"`, `SIG_FILE = "SHA256SUMS.sig"`, `BUNDLE_MANIFEST = "update.aegis"`, `INSTALLERS_DIR = "installers"`.
- `sums_for_dir(dir: &Path) -> Result<String, BundleError>`: the `SHA256SUMS` text for every file in `dir` (it skips the two top-level sums files).
- `verify_bundle_dir(dir: &Path, keys: &TrustedKeys) -> Result<BundleReport, BundleError>`; `BundleReport { key_id: String, release: Version, files: usize }`.
- `public_key_pem(keys: &TrustedKeys, key_id: &str) -> Option<String>`.
- `Issuer::sign_bundle_sums(&self, sums: &str) -> Result<[u8; 64], BundleError>` (feature `issuer`).

Bundle folder layout: `SHA256SUMS`, `SHA256SUMS.sig` (raw 64-byte Ed25519 signature over `SHA256SUMS`, update key), `update.aegis`, `installers/<file>` (each hash must be an artifact sha256 in `update.aegis`), optional `images.tar.gz`. File names: ASCII letters, digits, `.`, `_`, `-`, starting with a letter or digit.
