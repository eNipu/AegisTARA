## Problem & Goal
The desktop app is pinned to Slint's software renderer (`crates/aegis-shell/src/main.rs` selects `renderer_name("software")` on every platform) and uses Slint's default widget styling. On macOS this reads as a Windows-style app with soft text, which is the main "not solid on macOS" complaint behind D25. The goal is to make the same Slint UI look and feel native on macOS and Windows without changing layout or features: a GPU renderer with an automatic software fallback and an explicit `AEGIS_RENDERER=software` escape hatch, per-OS widget styles chosen at build time (`cupertino` on macOS, `fluent` elsewhere), System/Light/Dark appearance that follows the OS live, ⌘-based shortcuts generated from the one `shortcuts.rs` table, and system UI and monospace fonts with Japanese fallback. The renderer choice itself is human-gated: a spike on a Retina Mac and a Windows laptop produces screenshots and numbers, the owner picks, and the choice is recorded in ADR 0063 before implementation starts.

## Acceptance Criteria
1. **Renderer spike and ADR before implementation (`UI-07.2`, D25)**: Before any renderer code is merged, run a spike that builds the same app three ways — software, Skia and FemtoVG — and measures each on (a) one Retina Mac and (b) one Windows laptop, at 100 % and 150 % scale. For every combination record screenshots of the assets page, the attack tree canvas and a Japanese page; binary size; cold start time; and peak memory. Put the artefacts under `docs/spikes/platform-fidelity/` (or an equivalent path named in the ADR), fill the evidence table in `docs/adr/0063-platform-fidelity-renderer.md`, and change its `Status: proposed` only after the owner has picked from the screenshots. No measurements may be invented in the ADR; unmeasured cells stay `TBD`.
2. **GPU renderer with automatic software fallback (`UI-07.1`)**: The window selects the chosen GPU renderer by default. If it cannot start (virtual desktop, remote session, old driver, missing library), the app retries once on Slint's software renderer and continues; it logs exactly one line naming the renderer that failed and the fallback, shows no error dialog, and the app remains usable.
3. **`AEGIS_RENDERER=software` setting (`UI-07.1`)**: Setting `AEGIS_RENDERER=software` forces the software renderer before any GPU initialisation, with no GPU probe and no fallback log line. An unrecognised `AEGIS_RENDERER` value is ignored with one warning line and the default selection; the variable is documented in `main.rs`'s environment table and in the deployment/release notes, and the `main.rs` module comment that says the window "always uses Slint's software renderer" is corrected.
4. **D5, `cargo-deny` and offline build (`UI-07.3`, NFR-04, NFR-06)**: The renderer and every new transitive dependency pass the D5 license review and `scripts/deny.sh` (shipped graph, not dev-only). `cargo build --offline --release -p aegis-shell` succeeds from a warmed vendor/cache with no network access, for the offline bundle (job 100). If Skia's build-time download cannot be made offline-safe, either vendor the prebuilt archive with a checksum and a license notice, or choose FemtoVG; record which in ADR 0063.
5. **Per-OS widget style from `build.rs` (`UI-07.4`)**: `crates/aegis-shell/build.rs` reads `CARGO_CFG_TARGET_OS` and passes `CompilerConfiguration::with_style`: `cupertino` for `macos`, `fluent` for `windows`, `linux` and every other target. `Theme` colors and the existing brand tokens stay on top of the style, so pages, tables, dialogs and the canvas keep their current layout and colors in both styles. The selected style is visible in a build-time log line or a `cfg`-gated test, and cross-compiling for another target does not silently pick the host style.
6. **System, Light and Dark appearance (`UI-07.5`)**: The default is System: the app reads the OS light/dark appearance at start and follows live changes without a restart. A setting offers System, Light and Dark, persists through the existing client settings, and applies immediately. The splash, About and brand headers stay obsidian in every mode; no page keeps stale colors after a live switch.
7. **macOS ⌘ shortcuts from one table (`UI-07.6`)**: Every shortcut shown in menus, tooltips, the keyboard cheat sheet and the command palette comes from `crates/aegis-shell/src/shortcuts.rs` via `shortcuts::keys` (`⌘`/`⌥`/`⇧` on macOS, `Ctrl`/`Alt`/`Shift` elsewhere). On macOS the menus use ⌘ labels and the standard App menu accelerators, and no `.slint` file or Rust string hard-codes a `Ctrl+` label. This includes the two existing hard-coded strings in `ui/app.slint` (the inline-edit comment and the `@tr("Plain text. Ctrl+Enter saves, Escape cancels.")` hint, around lines 2738 and 2763): the hint takes its key text from the table (a `@tr` argument), and the translation catalogs are updated to match. A test iterates the table and asserts each `mac` label starts with a macOS modifier and contains no `Ctrl`, and each `other` label contains no `⌘`.
8. **System UI and monospace fonts (`UI-07.7`)**: UI text uses the platform UI font (SF Pro on macOS, Segoe UI Variable on Windows) with Hiragino Sans and Yu Gothic UI fallback for Japanese; monospace surfaces (JSON/detail panes, report previews, identifiers) use the system monospace font (SF Mono on macOS, Cascadia Mono on Windows). Fonts are referenced by family name with fallbacks rather than bundled, so no new font licence is added; Japanese pages and pseudo-locale screenshots show no tofu and no clipped text.
9. **Headless screenshot tests stay on software (`src/headless.rs`)**: The screenshot and monkey test platforms keep using Slint's software renderer explicitly, independent of `AEGIS_RENDERER` and of the chosen GPU renderer, so CI needs no GPU and renders deterministically. `tests/ui.rs`, `tests/pages.rs`, `tests/i18n.rs`, `tests/small_windows.rs` and `tests/monkey.rs` still pass unchanged in intent, and a test sets `AEGIS_RENDERER` to a GPU value, builds the headless platform (`MinimalSoftwareWindow`, no renderer-name lookup) and still renders a frame, proving the test path never reads the variable.
10. **No layout or feature change (`D25`)**: Every existing page and flow looks the same in structure, copy and keyboard behaviour under both styles and all three appearance modes; only rendering quality, widget chrome, fonts and modifier labels differ. The macOS menu bar (UI-07.8) is attempted with Slint's `MenuBar`; if the chosen backend does not support the system menu bar, the gap is recorded in ADR 0063 and no custom workaround is built.

## Open questions
1. **Which renderer does the owner pick: software, Skia or FemtoVG?** **Answered 2026-10-30: Skia** (see `rework.md` and ADR 0063). It stays provisional until question 2 is satisfied, and the FemtoVG switch below still applies if `UI-07.3` fails. Original framing: this should be answered from the spike screenshots and numbers, not from preference. Recommended default: **Skia** with a vendored prebuilt archive (UI-07.1's preference), provided UI-07.3 holds — D5 clean, `cargo-deny` clean, and `cargo build --offline --release` works from the vendored archive. If Skia cannot be made offline-safe or its text at 100 %/150 % on the Retina Mac is not clearly better, the recommended default changes to **FemtoVG** (UI-07.3's named fallback). Software stays the fallback and the test renderer, not the default.
2. **What spike evidence is required before the pick?** Both machines must produce, for each of software/Skia/FemtoVG at 100 % and 150 % scale: screenshots of the assets page, the attack tree canvas and a Japanese page; binary size (release, stripped, per renderer); cold start time to first painted frame (median of at least 5 launches, method recorded); peak memory after loading the `large` reference project. The Mac must be Retina, the Windows laptop must state its GPU, driver and Windows build. Also record build time, whether the build needs network access, and any build warnings. The owner reviews the screenshots side by side with a native Mac app at the same scale before answering; unanswered cells stay `TBD` in ADR 0063.
