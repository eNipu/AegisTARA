## Goal

A methodology pack can say that one setting preset conflicts with another (`conflicts_with`, an optional list of preset keys on a `control_kinds` entry), and the linter reports one warning per component or interface that has settings of both conflicting presets — never a block, because the consultant may be recording a real defect (CFG-09). The whole feature is model data plus one lint code plus one Problems-page arm; no op, no snapshot, no Slint change.

## Facts you need

- A setting preset in a pack is a `control_kinds` entry: `key`, `label`, optional `interface_kinds` (empty = for components), `rules` (1 to 16). It decodes into `ControlKindDef` (`crates/aegis-model/src/methodology/mod.rs` line 239) and builds into `ControlKindData` (line 803) with the typed index `ControlKind` (line 798). `Methodology::new` validates via `build_control_kinds` (line 1563); keys resolve through the `by_key` map, which is complete only after the first loop over all defs.
- A control applied as a setting carries `kind: Option<ControlKind>` (`crates/aegis-model/src/control.rs` line 366) and `targets: Vec<ItemIdx>` (line 364). `ItemIdx` is `Component(ComponentIdx) | Interface(InterfaceIdx)` (`crates/aegis-model/src/item.rs` line 57); `ItemRef` is its public-ID mirror (line 39). `Project::item_ref(Some(idx)) -> Option<ItemRef>` is at `crates/aegis-model/src/project.rs` line 7447.

- The client turns a code into a sentence in `pages::problem` (`crates/aegis-client/src/pages.rs` line 2396), an exhaustive match; the page is `pages::problems` (line 2795).
- The shipped ISO, CRA and STRIDE packs declare no conflicts and must stay byte-identical (builtin_pack/stride_pack compare the files with the writer's output). The writer must therefore skip the new field when the list is empty, exactly as it skips `interface_kinds` (pack.rs line 656).
