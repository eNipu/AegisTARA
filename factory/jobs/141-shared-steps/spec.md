# 141 Shared steps (BLK-01)

## Title
Shared attack steps (`BLK-01`): reusable `SharedStep` building blocks (visual ID `L`), `UseSharedStep` and `UnuseSharedStep` ops, rating ops targeting shared steps, atomic `MakeShared` and `Unshare` client edits, Shared building blocks page in group 4, and step inspector indicator

## Problem & Goal
Complex vehicle architectures repeat the same attack steps (for example, opening an unsealed enclosure or dumping external flash) across dozens of threat scenarios and attack trees. Re-rating, maintaining "through" links, or updating feasibility factors on every duplicate leaf is slow and error-prone (rule P7).

This job adds typed `SharedStep` building blocks (`L00`, `L01`, ...) that own feasibility ratings, factor levels, `via` item links, and attack types while attack-tree step nodes hold at most a reference slot (`shared: Option<SharedStepIdx>`). Analysts can rate a shared step once, link or unlink steps across any number of trees, convert an existing step into a shared step (`Edit::MakeShared`) or detach back to local step ratings (`Edit::Unshare`) in a single undoable command, browse usage on a new "Shared building blocks" page in group 4, and immediately see `"Shared step L03, used in 5 trees"` above the fields when inspecting a linked step.

## Acceptance Criteria
1. `SharedStep` entity and visual ID: `SharedStep` (`SharedStepId`, `SharedStepIdx`, `VisualPrefix::SharedStep` = `"L"`, `MAX_SHARED_STEPS = 4_096`), `ElementRef::SharedStep`, `EntityKind::SharedStep`, `Op::AddSharedStep`, `Op::RenameSharedStep`, `Op::RemoveSharedStep`, and `ProjectDiff::shared_steps` round-trip through op properties, inverse undo, `Project::eq` (comparing `via` by public `ItemRef`), and invariant checks (`cargo test --locked -p aegis-model --test shared_steps --test ops_properties`).
2. Widened step rating ops: `Op::SetStepFeasibility`, `Op::SetStepFactor`, `Op::SetStepVia`, and `Op::SetStepAttackType` take `target: StepTarget` (`StepTarget::Step(TreeId, NodeId) | StepTarget::Shared(SharedStepId)`), check/commit against `SharedStep` targets with exact inverses, count shared steps in `count_steps_via`, and maintain backward-compatible JSON op-log wire decoding (rejecting invalid `(tree, node, shared_step)` combinations with `StoreError::Decode`) (`cargo test --locked -p aegis-model --test store_limits --test shared_steps && cargo test --locked -p aegis-client --test undo_every_op`).
3. Node link slot and resolved evaluation: `StepLinks.shared: Option<SharedStepIdx>`, `Op::UseSharedStep`, and `Op::UnuseSharedStep` enforce `ModelError::StepIsRated { tree: TreeId, node: NodeId }` when the node has own ratings/`via`/attack type (distinct from existing `ModelError::NodeIsRated(NodeId)`), reject gate targets with `ModelError::NotAStep`, and enforce removal guards (`RemoveSharedStep` returns `SharedStepInUse` when linked by any step and `SharedStepIsRated` when carrying own ratings/`via`/attack type; `RemoveTreeNode`/`RemoveTree` reject linked steps with `NodeUsesSharedStep`). All evaluation, applicability, lint, diff, ceiling, and system accessors (`step_feasibility`, `step_factor*`, `step_via`, `step_attack_type`, `effective_step_feasibility`, `residual_step_feasibility`, `step_ceilings`, `entry_step_*`, `steps_via`, `lint_trees`, `tree_affected_by_controls`, `diff_risk_deltas`, `SystemUse::shared_step`) read from the referenced `SharedStep` (`cargo test --locked -p aegis-model --test shared_steps --test ops_properties`).
4. Incremental evaluation cache (`ProjectEvalCache`): `AddSharedStep`/`RemoveSharedStep` keep `shared_users` sized to `shared_steps.slot_count()`, and editing a `SharedStep` or applying `UseSharedStep` / `UnuseSharedStep` / `SetStep*` updates applicability when needed (`may_change_applicability`), marks/recomputes every `(TreeIdx, NodeId)` user and control ceiling (`update_control_*`), verified against independent hand-computed expected values and fresh `Project` evaluation across random mutations and shuffled-order runs (`cargo test --locked -p aegis-model --test shared_steps --test ops_properties`).
5. Persistence (`snapshot`, `op_log`, `workspace`): `SnapshotWire.shared_steps`, `TreeWire.step_shared` (and separate `own_step_*` getters so linked steps do not duplicate shared ratings on tree snapshots), workspace `shared/steps.json` (`LAYOUT` + `blame` + `Limit::SHARED_STEPS`), and old v1 fixtures load cleanly (`cargo test --locked -p aegis-model --test store --test workspace --test store_limits --test shared_steps`).
6. Client edits, tree diff, relations, and inspector line: `Edit::MakeShared`, `Edit::Unshare`, and `Edit::RemoveSharedStep` execute and undo as one batch each, restoring local step ratings/factors/`via`/attack type identically on `Unshare` and `RemoveSharedStep`; inspector `Edit::SetStep*` routes to the linked `SharedStep`; `clear_via_ops`, `clear_descriptions_before_removal`, `Edit::RemoveTreeNode`/`Edit::RemoveTree`, and `tree_diff.rs` handle shared steps undo-safely; `RELATIONS` registers `SHARED_STEP_VIA` and `SHARED_STEP_USED_IN` alongside `STEP_VIA`; `InspectorView.shared_note` produces `"Shared step L03, used in 5 trees"` (distinct-tree singular vs plural) above fields in EN/JA (`cargo test --locked -p aegis-client --test shared_steps --test relations --test inspector_view --test undo_every_op && cargo test --locked -p aegis-workbench --test inspector_view`).
7. Shared building blocks page and workbench table: `Page::SharedBlocks` (`PageLayout::Table`) sits in `PageGroup::Feasibility` right after `Page::Trees` (`Page::ALL` index 9, len 19), backed by `TableId::SharedSteps` (with `id`, `name`, `feasibility`, `via`, `attack-type`, and read-only `"Used in"` link column), `Folder::SharedSteps` under shared analysis and system owners (`Owner::Unassigned` empty, `Owner::Project` all, `Owner::System(s)` steps used by `s`), grid editing, locale/`.po` sync, and Slint `Pages`/`nav-entries` (`NavEntry { label, icon, group }`) sync (`scripts/ci.sh`).

## Decisions
- Use `pub enum StepTarget { Step(TreeId, NodeId), Shared(SharedStepId) }` on `Op::SetStepFeasibility`, `Op::SetStepFactor`, `Op::SetStepVia`, and `Op::SetStepAttackType`: concise type matches III.7 widening without multiplying four more op variants.
- Serialize `OpWire`/`OpView` for those four ops with optional top-level `tree`/`node` or `shared_step` fields instead of `#[serde(flatten)]`: `OpWire` uses `#[serde(deny_unknown_fields)]`, which forbids flatten while keeping existing JSON wire keys unchanged.
- Do not add `attacker_type` to `SharedStep`: `attacker_type` belongs to unbuilt job `139-attacker-types` and does not exist on `Methodology` or steps yet.
- Keep `Op::AddSharedStep { id, name, provenance }` minimal and make `Op::RemoveSharedStep` require unlinked (`SharedStepInUse`) and cleared (`SharedStepIsRated`): matches `RemoveAssumption`/`RemoveSecurityControl` so every op has a deterministic exact inverse.
- Introduce distinct `ModelError::StepIsRated { tree: TreeId, node: NodeId }` for `UseSharedStep`: `ModelError::NodeIsRated(NodeId)` already exists in `error.rs` and `check_remove_tree_node`, so a separate struct variant avoids colliding with existing removal errors and callers.
- Resolve `lint_trees` (`AttackTreeStepUnrated`, `AttackTreeStepIncompleteFactors`, `RedundantStepFeasibility`, `StepSettingsIncomplete`) through `SharedStep` on linked steps instead of adding separate `SharedStep` lint codes: preserves `lint_soundness` (`!has_errors => evaluate_tree == Ok`) per tree node without breaking unused building-block drafts or `Problems` table rows.
- Add `Limit::SHARED_STEPS` and `SharedStepsCap` in persistence slice `141d`: `141a` enforces `MAX_SHARED_STEPS` in `Project::validate` (`TooManySharedSteps`) while `141d` decodes bounded `shared_steps` lists in snapshots and `shared/steps.json`.
- Represent `"Used in"` as `RelationKey::SHARED_STEP_USED_IN` (`from: ElementKind::SharedStep, to: &[ElementKind::Step], many: true, link: None, unlink: None`) while keeping `RelationKey::STEP_VIA` reading own step `via` when unshared: satisfies `table.rs`/`grid/` link-column invariants and `tests/relations.rs` 1:1 registry parity without duplicate `(Step, Item)` links.
- Use `icons/workflow.svg` for `Page::SharedBlocks` in `app.slint` `nav-entries`: matches sidebar conventions (`box.svg`/`workflow.svg` exist whereas `blocks.svg` does not) and avoids Slint UI design work.
- Add `Engine` cache storage `shared_users: Vec<Vec<(TreeIdx, NodeId)>>` and `node_shared: HashMap<(TreeIdx, NodeId), SharedStepIdx>`: keyed by stable `NodeId` instead of `NodeIdx` because adding/removing nodes shifts indices inside a tree.
- Add separate Fluent messages for singular vs plural (`inspector-shared-step-line-one` and `inspector-shared-step-line`) using distinct trees count: matches codebase pattern and avoids Fluent numeric selector pitfalls with string arguments.
