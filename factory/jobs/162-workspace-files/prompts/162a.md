# Build prompt: 162a Write a project as workspace files

You are implementing one small change in the AegisTARA repository (a Rust workspace).
Work only inside `factory/worktrees/162-workspace-files/`, on branch `factory/162-workspace-files`.

## Goal
A `Project` is saved today as one JSON snapshot. After this slice, `aegis-model` can also
turn a project into a list of small files (path and bytes), one per kind of element and one
per attack tree, so a project can live in a folder that git can diff. This slice only
**writes**. Reading comes in the next slice. Nothing touches the disk.

## Read first (only these)
- `crates/aegis-model/src/store/snapshot.rs` lines 20-75: `SnapshotView` and the section
  views (`Assets`, `Damages`, `Threats`, `Trees`, ...). These already serialize every section.
- `crates/aegis-model/src/store/snapshot.rs` lines 745-775: `Project::save`, to see how a
  `SnapshotView` is built.
- `crates/aegis-model/src/store/mod.rs` lines 1-80: module layout and how limits are documented.
- `crates/aegis-model/tests/store.rs`, first 60 lines: how tests build projects and use `tests/common`.
- `factory/lessons.md` in the main checkout: lines tagged `[builder]`.

## Do
1. Add `crates/aegis-model/src/store/workspace.rs` and declare it in `store/mod.rs`.
2. Add and export from `lib.rs`:
   ```rust
   pub struct WorkspaceFile { pub path: String, pub bytes: Vec<u8> }
   impl Project {
       /// O(n) in project size.
       pub fn to_workspace_files(&self) -> Result<Vec<WorkspaceFile>, StoreError>;
   }
   ```
3. Implement it by reusing the snapshot serializer, not by writing a second one: build the
   same `SnapshotView` that `Project::save` builds, turn it into a `serde_json::Value`
   (add a `pub(super)` helper in `snapshot.rs` for this), then split its top-level keys into files:

   | Path | `kind` | Snapshot keys it holds |
   |---|---|---|
   | `aegis.json` | `workspace` | `methodology`, `languages` |
   | `descriptions.json` | `descriptions` | `descriptions` |
   | `review-marks.json` | `review-marks` | `review_marks` |
   | `shared/damage.json` | `damage` | `damage_scenarios` |
   | `shared/controls.json` | `controls` | `security_controls` |
   | `shared/goals.json` | `goals` | `cybersecurity_goals` |
   | `shared/claims.json` | `claims` | `cybersecurity_claims` |
   | `systems/main/item.json` | `item` | `components`, `interfaces`, `data_flows`, `trust_boundaries` |
   | `systems/main/assets.json` | `assets` | `assets` |
   | `systems/main/threats.json` | `threats` | `threat_scenarios` |
   | `systems/main/trees/<visual-id>.json` | `tree` | `attack_trees`, holding exactly one tree |

   - The tree file name is the tree's visual ID in lower case (for example `at01.json`).
   - Every file is one JSON object whose first three keys are `"format":"aegis-workspace"`,
     `"version":1`, `"kind":"<kind>"`, followed by the snapshot keys from the table with their
     values unchanged.
   - `aegis.json` is always written. Any other file is written only when at least one of its
     keys is present in the snapshot value.
   - Pretty-print with two spaces and end each file with one newline.
   - Return the files sorted by `path`.
   - If the snapshot value has a top-level key that is not in the table (other than `format`
     and `version`), return an error. Do not drop it silently.
4. Add `crates/aegis-model/tests/workspace.rs` with these tests:
   - `layout_covers_every_snapshot_key`: build a project that has at least one of every
     element kind (use the helper in `tests/common` that records every op; find it with
     `grep -n "every_op" crates/aegis-model/tests/common/*.rs`), save it as a snapshot, and
     check that every top-level snapshot key except `format` and `version` appears in exactly
     one workspace file.
   - `same_project_same_bytes`: calling `to_workspace_files` twice gives equal paths and bytes.
   - `rename_changes_one_line_in_one_file`: rename one asset; exactly one file differs from
     before, and the two versions differ in exactly one line.
   - `empty_project_writes_only_the_workspace_file`.
   - `one_file_per_tree_named_by_visual_id`.
   - `every_file_starts_with_the_envelope`.
