# Build prompt: 162b Read workspace files back into a project

You are implementing one small change in the AegisTARA repository (a Rust workspace).
Work only inside `factory/worktrees/162-workspace-files/`, on branch `factory/162-workspace-files`.

## Goal
Slice 162a added `Project::to_workspace_files`, which writes a project as a list of small
JSON files. After this slice, `aegis-model` can read such a list back into an equal project.
The input is untrusted: it may come from a customer or an attacker. This slice covers the
good path and the envelope checks; the full list of refusals and the size caps come in 162c.

## Read first (only these)
- `crates/aegis-model/src/store/workspace.rs`: all of it (written in 162a). The path and
  `kind` table there is the layout you read.
- `crates/aegis-model/src/store/snapshot.rs`, the `Project::load` function (find it with
  `grep -n "pub fn load" crates/aegis-model/src/store/snapshot.rs`), first 20 lines: it reads
  through a capped reader and validates everything. You will call it, not copy it.
- `crates/aegis-model/src/error.rs`, `pub enum StoreError` (find with `grep -n "pub enum StoreError"`): how errors are shaped and documented.
- `crates/aegis-model/tests/store_properties.rs` lines 1-110: the round-trip property test and its `seeds()` generator.
- `factory/lessons.md` in the main checkout: lines tagged `[builder]`.

## Do
1. In `store/workspace.rs` add, and export through `lib.rs`:
   ```rust
   impl Project {
       /// O(n) in the total size of the files.
       pub fn from_workspace_files<'a, I>(files: I, methodology: Arc<Methodology>)
           -> Result<Project, StoreError>
       where I: IntoIterator<Item = (&'a str, &'a [u8])>;
   }
   ```
   The files may arrive in any order.
2. Implement it this way, so every check the snapshot reader has today still runs:
   1. For each file: match its path against the layout table from 162a. Parse it as JSON.
      Check that `format` is `aegis-workspace`, `version` is `1`, and `kind` is the kind the
      table gives for that path.
   2. Put the snapshot keys of all files back into one JSON object, adding
      `"format":"aegis-project"` and the snapshot's version number. Tree files each hold a
      one-element `attack_trees` list: join them, ordered by path.
   3. Serialize that object to bytes and return `Project::load(bytes, methodology)`.
3. Add these `StoreError` variants, each with a doc comment and a doc test like its
   neighbours, and each carrying the path (a `String` you have already checked is short):
   `WorkspacePath { path }` (not in the layout), `WorkspaceEnvelope { path, problem }` where
   `problem` is a small enum (`Format`, `Version`, `Kind`, `Json`), and
   `WorkspaceMissing { path }` (for `aegis.json`).
4. Add to `tests/workspace.rs`:
   - `round_trip_fixture`: load `tests/fixtures/project-v1.json` with `Project::load`, write
     workspace files, read them back, and check that `save()` gives the same bytes as before.
   - `round_trip_every_kind`: the same for the project with one of every element kind.
   - `file_order_does_not_matter`: reverse the list and get an equal project.
   - `missing_workspace_file`, `unknown_path`, `wrong_format`, `newer_version`,
     `kind_does_not_match_path`, `not_json`: each returns the matching error and names the path.
5. Add `crates/aegis-model/tests/workspace_properties.rs`: one property test per
   methodology (as `store_properties.rs` does) that builds a random project from `seeds()`
   and checks `from_workspace_files(to_workspace_files(p)).save() == p.save()`.

## Do not
