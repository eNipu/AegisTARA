## Do
1. Limits, each a documented public constant with a `Limit` case and
   `StoreError::LimitExceeded`:
   - `MAX_WORKSPACE_FILES`: the largest number of files. Choose it from the existing cap on
     attack trees per project plus the ten fixed files, and say so in the doc comment.
   - `MAX_WORKSPACE_FILE_BYTES`: the largest single file.
   - The sum of all file sizes may not exceed the existing `MAX_PROJECT_FILE_BYTES`.

   Check all three **before parsing any JSON**. Count files as the iterator yields them and
   stop at the cap; do not collect the iterator first.
2. Path rules, checked before the layout match. Refuse with `StoreError::WorkspacePath`:
   an empty path; a leading `/`; a `\`; a `..` or `.` segment; any byte outside lower-case
   ASCII letters, digits, `-`, `.` and `/`.
3. New refusals, each a `StoreError` variant with a doc comment and doc test:
   - `WorkspaceDuplicatePath { path }`: the same path twice.
   - `WorkspaceUnknownField { path, field }`: a top-level key that is not the envelope or one
     of that kind's snapshot keys (`field` cut to the existing key length cap).
   - `WorkspaceTreeName { path }`: a tree file that does not hold exactly one tree, or whose
     file name is not that tree's visual ID in lower case.
   - `WorkspaceMethodology { path }`: the methodology key or version in `aegis.json` differs
     from the one passed in. If `Project::load` already reports this, map its error to this
     variant instead of adding a second check.
4. When `Project::load` fails on the joined snapshot, wrap its error so the caller learns
   which file to open: `StoreError::InWorkspace { path, source }`, where `path` is the file
   that supplied the snapshot key the inner error is about, or `aegis.json` when that cannot
   be told. Two cases must name files exactly, with a test each:
   - the same element ID in two tree files: the error names the second file;
   - a threat that refers to an asset that is in no file: the error names
     `systems/main/threats.json`.
5. A refusal never returns a partly built project.
6. Add `crates/aegis-model/tests/workspace_limits.rs`: one test per rule in steps 1 to 4.
   Each limit has a case just under (accepted) and just over (refused). Add one test that
   every error's `Display` text is at most 512 bytes when the input path and field are 1 MB long.
