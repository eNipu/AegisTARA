## The format (copy exactly)
`control_kinds` goes after `attack_types` and before `translations`, at the same indent. One entry, with `interface_kinds` left out for a component preset; `rules` keys in alphabetical order:
```json
    "control_kinds": [
      {
        "key": "secure-boot",
        "label": "Secure boot",
        "rules": {
          "bootloader-exploit": "low",
          "firmware-modification": "low"
        }
      },
      {
        "key": "debug-port-locked",
        "label": "Debug port locked",
        "interface_kinds": [
          "debug"
        ],
        "rules": {
          "debug-access": "low",
          "flash-read-out": "low"
        }
      }
    ],
```
In `translations.ja`, after the `attack_types` map: `"control_kinds": { "<key>": "<label>", ... }` with keys in alphabetical order, one per line.
The files must equal the writer's output byte for byte; the tests tell you when they do not. If a test fails on formatting, write the definition with `MethodologyDef::write_pack` in a scratch test and copy its output; do not hand-tune.
