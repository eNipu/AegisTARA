# Build prompt: 124f Commands: add a preset setting, refuse a wrong fit, use the pack's values

## Goal
The client gets the commands behind "Add setting": creating a setting from a pack preset and applying it is one batch and one undo step, with the preset's rules copied into the control. A preset that does not fit the element (a debug-port preset on a whole ECU) is refused with a sentence the user can read. A second command sets a changed setting back to the pack's values, also in one undo step. The screen that calls these commands is built later in the GPUI shell; this slice has no UI.

## Facts from earlier slices
- Model: `Op::SetControlKind { control: ControlId, kind: Option<ControlKind>, provenance }`; `SecurityControl::kind() -> Option<ControlKind>`; `SecurityControl::rules() -> &[ControlRule]` and `rule_for(attack_type) -> Option<FeasibilityLevel>`; `ControlRule::attack_type()`, `ControlRule::ceiling()`.
- `Methodology::control_kinds()` (iterator of `ControlKind`, pack order), `control_kind_label(kind) -> Option<&str>`, `control_kind_rules(kind) -> &[ControlRule]` (sorted by attack type), `control_kind_interface_kinds(kind) -> &[InterfaceKind]` (empty: the preset is for components), `interface_kind_label(kind) -> Option<&str>`.
- `Project::control_kind_fits(kind, target: ItemRef) -> bool`; `Project::control_differs_from_kind(control: ControlIdx) -> bool`.
- A control with a kind cannot be removed until the kind is cleared; `Edit::RemoveControl` already clears it.
- `MAX_CONTROL_RULES` is 16: a control may never hold more than 16 rules, also in the middle of a batch.
- ISO pack (`Methodology::iso21434_r155()`): interface kinds in order `can`(0, label "CAN"), `ethernet`(1), `wireless`(2), `debug`(3, label "Debug"), `cellular`(4), `usb`(5). Presets in order: `secure-boot`(0, label "Secure boot", for components, rules `firmware-modification -> low`, `bootloader-exploit -> low`), `secure-flash`(1), `flash-read-protection`(2), `hsm-key-storage`(3), `housing-sealed`(4), `debug-port-locked`(5, label "Debug port locked", for `debug` interfaces, rules `debug-access -> low`, `flash-read-out -> low`), `debug-port-fused`(6), `secure-diagnostics`(7, for `can`, `ethernet`, `usb`), ...

   - preset for interfaces, target a component: `"<label>" is a setting for <kinds> interfaces; it cannot be applied to a component`

Otherwise walk `m.attack_types()` in order and compare `ctrl.rule_for(t)` with the preset's rule for `t`; first push a `SetControlRule { ceiling: None }` for every attack type the control has a rule for and the preset does not, then a `SetControlRule { ceiling: Some(level) }` for every attack type whose preset level differs from the control's (or is missing). Clears come first so the control never passes 16 rules.
