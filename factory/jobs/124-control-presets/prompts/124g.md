4. `docs/adr/0070-control-presets.md`, short, in the layout of ADR 0064 (status accepted, job 124-control-presets, requirements CFG-06, builds on ADR 0064 and ADR 0011). State these decisions and their reasons:
   - `control_kinds` is an optional list in the pack (after `attack_types`): `key`, `label`, optional `interface_kinds`, `rules` as an object from attack type key to feasibility level key; labels per language in `translations.<lang>.control_kinds`. No `interface_kinds` means the preset is for components. At most 64 presets, 1 to 16 rules each; every key must be declared in the same pack.
   - Creating a setting from a preset copies the rules into the control and records the kind with `Op::SetControlKind`. A later pack version never changes a saved result without an op. Considered and rejected: reading the rules from the pack at evaluation time (a pack update would silently change signed numbers).
   - The model stores the kind and does not enforce the fit; the client command refuses a wrong fit with a sentence. Enforcing it in the model would need guards on `SetInterfaceKind` and `ApplyControl` for no user gain.
   - `RemoveSecurityControl` is rejected with `SecurityControlHasKind` while a kind is set, so the inverse of a removal stays exact; the client's remove batch clears the kind first.
   - A pack must not drop a preset key between versions: a snapshot stores the kind by key and fails to load on an unknown key, as for attack types.
   - `ControlRulesDifferFromKind` is a warning, not a new severity; `Edit::UsePackValues` is one undo step and clears rules before it sets them, so the 16-rule cap holds inside the batch.
   - The built-in presets (12 ISO, 8 CRA, 8 STRIDE) are editable examples. CRA and STRIDE presets are for components only because those packs declare no interface kinds.
   - Left for the GPUI shell: the inline filtered list, its keyboard handling, the "(pack preset)" subtitle, the "Use the pack's values" button and the inline error. No Slint work was done.
