## Goal
A project can hold systems (Brake, ADAS, Gateway), and the user looks at one, a few or all of them (the "view"). After this slice the overview data has one row per system with its components, assets, threats, highest risk after controls and boundary flows, plus a total row, and the rows add up to the total. This is the table a consultant shows in a steering meeting, so a total that does not match would cost trust. The screen is built later in another UI toolkit; this slice delivers the data and its tests only.

Facts about what exists:
- Model: `project.system_use() -> SystemUse`; `SystemUse::asset(AssetIdx)` and `SystemUse::threat(ThreatIdx)` return a `SystemSet` with at most one system; `SystemUse::ids(set)` iterates its `ElementId`s; `SystemSet::is_empty()`. `project.component_system(ComponentIdx) -> Option<ElementId>` (children follow their top-level ancestor). Iterators `project.components()`, `project.assets()`, `project.threat_scenarios()` each yield `(Idx, Id, &T)`. `project.elements(ElementKind::System)` yields `(ElementId, &Element)` in ID order; `Element::name()`.
- Risk after controls: `ws.cache().evaluate_residual_risk(project, threat_id)` returns `Result<&ThreatRisk, ModelError>`; `ThreatRisk::max_risk() -> Option<RiskLevel>`. The methodology (`project.methodology()`) orders levels with `m.risk_levels()`, lowest first; `pages.rs` has the private helper `risk_view(m, level) -> Option<RiskView>` (label and tone) used by `threat_risks`.
- Client, `crates/aegis-client/src/systems.rs`: `SystemView` (`all()`, `only(id)`, `of(ids)`, `is_all()`, `contains(id)`, `normalized(&Project)`).
