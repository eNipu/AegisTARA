## Goal
A project can hold systems (Brake, ADAS, Gateway); each top-level component is in at most one, and its children follow it. After this slice the model can say which data flows link two systems (a **boundary flow**), and the linter warns about a boundary flow that nobody analysed, the same way it already warns about a flow that crosses a trust boundary. The links between systems are where a vehicle-level analysis finds what a per-ECU analysis misses.

Facts about what exists:
- `Project::component_system(idx: ComponentIdx) -> Option<ElementId>` in `crates/aegis-model/src/system.rs`: the system of the component's top-level ancestor.
- `Project::data_flow(idx: DataFlowIdx) -> Option<&DataFlow>`; `DataFlow::from()` and `DataFlow::to()` return a `ComponentIdx`.
- `Project::element_count(ElementKind::System) -> usize`.
- The lint `LintCode::BoundaryCrossingDataFlowWithoutThreat { flow: DataFlowId }` fires when a flow crosses a trust boundary and neither end component has a bound asset with a threat scenario. `Project::lint()` sorts all findings at the end, so the order you push in does not matter.
