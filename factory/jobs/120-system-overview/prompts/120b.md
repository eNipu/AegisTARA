## Goal
A project can hold systems (Brake, ADAS, Gateway). A data flow whose two ends are in different systems is a boundary flow. After this slice the client rows of the item definition page say which flows are boundary flows, between which systems, how many threat scenarios cover them and whether none does; and each row of the Systems table says how many boundary flows the system has and with whom. The screen is built later in another UI toolkit; this slice delivers the data and its tests only.

Facts about what exists:
- Model: `Project::boundary_flow(idx: DataFlowIdx) -> Option<(ElementId, ElementId)>` gives (source system, destination system) for a boundary flow and `None` otherwise. `Project::component_system(ComponentIdx) -> Option<ElementId>`. `Project::element_count(ElementKind::System)`.
- Model iterators: `project.data_flows()` yields `(DataFlowIdx, DataFlowId, &DataFlow)`; `DataFlow::from()`, `to()` are `ComponentIdx`; `project.threat_scenarios()` yields `(ThreatIdx, ThreatId, &ThreatScenario)`; `ThreatScenario::asset() -> AssetIdx`; `project.asset(idx) -> Option<&Asset>`; `Asset::component() -> Option<ComponentIdx>`; every index type has `.index() -> usize`.
- Client: `crate::systems::system_name(project, id) -> Option<String>`; `SystemRow` and `system_rows(ws)` in `crates/aegis-client/src/systems.rs`; `DataFlowRow`, `DataFlowDetail`, `data_flow_rows(ws)`, `data_flow_detail(ws, id)` and the private `flow_crosses_boundary(project, df)` (trust boundaries) in `crates/aegis-client/src/pages.rs`.
- The lint counts a flow as covered when its source or destination component has a bound asset with a threat scenario. Use the same rule here.
