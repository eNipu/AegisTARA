# Build prompt: 120g The Versions comparison within the view

You are implementing one small change in the AegisTARA repository (Rust workspace).
Work only inside `factory/worktrees/120-system-overview/`, on branch `factory/120-system-overview`.

## Goal
A project can hold systems (Brake, ADAS, Gateway), and the user looks at one, a few or all of them (the "view"). The Versions page compares the project with a saved baseline and lists what was added, removed and changed and which risks moved. After this slice that list covers only the view, and its summary says how many more changes lie outside it, so the owner of the Brake analysis reads the Brake changes without losing sight of the rest.

Facts about what exists:
- `pages::comparison(base: &Project, baseline: &str, current: &Project) -> Result<Comparison, ModelError>` in `crates/aegis-client/src/pages.rs` builds `Comparison { baseline, summary, lines: Vec<DiffLine> }`; `DiffLine { kind, text }` with `kind` one of `Added`, `Removed`, `Changed`, `Risk`. It writes, in this order: components (added, removed, changed), a "moved from … to …" line for each changed component whose system changed, interfaces, data flows, trust boundaries, systems, assets, damage scenarios, threat scenarios, attack trees, security controls, goals, claims, then one `Risk` line per threat whose risk moved.
- `report/doc.rs` and several tests call `pages::comparison`; its signature and its output must stay.
- Systems of an element: `project.system_use() -> SystemUse`; `crate::systems::selection_systems(project, &usage, Selection) -> Option<SystemSet>` (`None` when the element is not in that project); `SystemUse::set_of(ids) -> SystemSet`; `SystemSet::shows_in(view_set)` is true when the set is empty or shares a system with the view. `project.component_system(ComponentIdx) -> Option<ElementId>`.
- `crate::systems::SystemView`: `all()`, `only(id)`, `of(ids)`, `is_all()`, `contains(id)`, `systems()`. `crate::systems::view_menu(project, view) -> Option<ViewMenu>` has `chip: String` ("Brake", "Brake + ADAS").
- Session: `crates/aegis-client/src/session.rs` calls `pages::comparison(base, name, open.ws.project())` when the page is `Page::Versions` (search for `pages::comparison(`); the view is `open.ui.system_view`, already normalized against the current project.

## Do
1. `pages.rs`:
   ```rust
   /// Compares `base` with `current` and keeps the lines `view` shows.
   /// With all systems this is `comparison`. Time as `comparison`, plus
   /// O(project) for the systems of both projects.
   ///
   /// # Errors
   ///
   /// The model's error if the two use different methodologies.
   pub fn comparison_in(
       base: &Project,
       baseline: &str,
       current: &Project,
       view: &crate::systems::SystemView,
   ) -> Result<Comparison, aegis_model::ModelError>
   ```
   `comparison` becomes a call to it with `SystemView::all()`.
2. `Comparison` gains two fields:
   - `scope: Option<String>`: the view's chip text from `view_menu(current, view)`, `None` for all systems.
   - `hidden: usize`: the number of lines left out.
3. The rule, when `view.is_all()` is false. Resolve the view in each project on its own: `v_cur = cur_usage.set_of(view.systems())`, `v_base = base_usage.set_of(view.systems())`. Do not normalize the view here.
   - An `Added` or `Changed` line of an element shows when the element's set in `current` `shows_in(v_cur)`.
   - A `Removed` line shows when the element's set in `base` `shows_in(v_base)`.
   - The "moved from … to …" line of a component shows when its old system or its new system is in the view (`view.contains`), compared by ID.
   - A system line (added, removed, renamed) shows when that system is in the view.
   - A `Risk` line shows by its threat: in `current` when the threat exists there, else in `base`.
   - An element that `selection_systems` cannot place shows.
4. The summary counts only the shown lines. When `hidden > 0`, append ` {hidden} more outside this view.` to it. When nothing is shown and `hidden > 0`, the summary is `Nothing changed in this view since this baseline. {hidden} more outside this view.`
5. `session.rs`: on the Versions page call `pages::comparison_in(base, name, open.ws.project(), &open.ui.system_view)`.
6. Tests in `crates/aegis-client/tests/combined.rs`. Fixture: two systems, Brake and ADAS, and a component in no system. Take `base` as a clone of the project (`ws.project().clone()`) at the point each test needs, so both sides share the methodology.
   - `base` taken right after the systems exist and before any other element: then add one element of **every** kind for Brake, for ADAS and for no system (component, interface, data flow, trust boundary, asset, damage scenario, threat, tree, control, goal, claim). Each system needs two components so that its data flow and its trust boundary stay inside it; link the damage scenario, tree, goal and claim to that system's threat and apply the control to its component, as the fixture in `crates/aegis-client/tests/systems_view.rs` lines 256-372 does. For the view `only(brake)`, check per kind that the Brake line and the no-system line are there and the ADAS line is not. Check `hidden` equals the number of lines `comparison` gives minus the lines shown.
   - Removed: remove one Brake threat and one ADAS threat after taking `base`; the view `only(brake)` shows only the Brake removal.
   - Moved: move a component from ADAS to Brake; the line shows in `only(brake)` and in `only(adas)`; with a third system `only(gateway)` it does not.
   - System lines: rename ADAS; the line shows in `only(adas)` and not in `only(brake)`.
   - Risk: rate threats so one Brake risk and one ADAS risk move; the view `only(brake)` has one `Risk` line.
   - Summary: the counts match the shown lines and the text ends with ` {hidden} more outside this view.`; `scope` is `Some("Brake")`.
   - `comparison_in(.., &SystemView::all())` equals `comparison(..)` and has `scope: None`, `hidden: 0`.
