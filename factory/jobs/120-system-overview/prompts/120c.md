## Goal
A project can hold systems (Brake, ADAS, Gateway). There are no links between attack trees of different systems; instead an attack step names the component or interface it goes through ("via"), and that item may belong to another system. After this slice the via chip of the tree and the step inspector name that other system ("GW · Gateway"), so a reviewer of the Brake analysis sees where an attack leaves Brake. A test also shows that the other system's settings cap the step and that the risk is the same whichever systems the user looks at.

Facts about what exists:
- Model: `project.step_via(tree: TreeIdx, node: NodeIdx) -> Option<ItemRef>`; `ItemRef::Component(ComponentId)` or `ItemRef::Interface(InterfaceId)`; `project.component_idx(&id)`, `project.interface_idx(&id)`, `project.interface(idx)` with `Interface::component() -> ComponentIdx`; `project.component_system(ComponentIdx) -> Option<ElementId>` (the system of the top-level ancestor).
- Model: `project.system_use() -> SystemUse` (one pass over the project); `SystemUse::tree(TreeIdx) -> SystemSet` is the set of systems whose threats link the tree; `SystemUse::set_of([id]) -> SystemSet`; `SystemSet::is_empty()`, `SystemSet::intersects(other)`. `project.element_count(ElementKind::System)`.
- Client: `crate::systems::system_name(project, id) -> Option<String>`; `view::through_label(project, item) -> String` gives "ADAS ECU" or "ADAS ECU / JTAG"; `NodeStyle.via: Option<String>` is the chip text set in `tree_scene`; `Inspector` is the step panel built by `inspector(ws, ui)`.
- Client: `crate::systems::{SystemView, filter_page}` and `pages::risk_rows(ws)`; `filter_page(project, &view, Page::Risks, &mut PageData)` keeps the risk rows the view shows.
