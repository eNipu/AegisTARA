You are implementing one small change in the AegisTARA repository (Rust workspace).

## Goal
The outline editor now shows what each step goes through and its attack type
(` | through: C00 | type: debug-access`), and applying the text sets, changes or clears them with
the existing `SetStepVia` and `SetStepAttackType` ops, in the same undo step as the tree change.
An ID or key that does not exist is an error that names the line, and nothing is applied. This
lets a consultant fill both values for a whole tree in one pass instead of one inspector pick per
step.

## Facts you need (from slice 122da, already on this branch)
In `crates/aegis-client/src/outline.rs`:
- `pub struct StepNote { pub line: usize, pub through: Option<String>, pub attack_type: Option<String> }`
- `pub struct ParsedOutline { pub tree: AttackTree, pub notes: Vec<(NodeId, StepNote)> }`: one
  note per step of the new tree (first line), none for gates; `None` means absent or `-`.
- `pub fn parse_outline_annotated(text: &str, previous: Option<&AttackTree>) -> Result<ParsedOutline, OutlineError>`
- `pub fn to_outline_with<F>(tree: &AttackTree, note: F) -> String where F: FnMut(NodeIdx) -> (Option<String>, Option<String>)`:
  `note` is called for steps and returns (through, attack type).
- The writer (`tail_of`, lines 173-190) writes the two values as they come. The reader
  (`read_tail`, lines 252-288) cuts the line at each ` | `, trims the value, refuses an empty
  value and reads `-` as "none". So a value that is empty, is `-`, or contains ` | `, a `:`, a
  space or a line break does not read back the same, and a line break adds a line to the outline.
  This slice is the first to pass values in, so it closes that gap (step 7).
- The values this slice passes in are safe by construction: a visual ID is letters followed by
  digits (`C00`, `IF00`), and the model only accepts an attack type key that matches
  `[a-z][a-z0-9_-]{0,63}` (`check_key` in `crates/aegis-model/src/methodology/mod.rs`).

Model API (`aegis_model`):
- `Project::step_via(TreeIdx, NodeIdx) -> Option<ItemRef>`, `Project::step_attack_type(TreeIdx, NodeIdx) -> Option<AttackType>`
- `ItemRef::Component(ComponentId)` / `ItemRef::Interface(InterfaceId)`
- `Project::components()` yields `(ComponentIdx, ComponentId, &Component)`, `Project::interfaces()` yields `(InterfaceIdx, InterfaceId, &Interface)`
- `Project::component_idx(&ComponentId)`, `Project::interface_idx(&InterfaceId)`
- `Project::component_visual_id(ComponentIdx) -> Option<String>` (`C00`), `Project::interface_visual_id(InterfaceIdx) -> Option<String>` (`IF00`)
- `project.methodology().attack_type(key: &str) -> Option<AttackType>`, `.attack_type_key(AttackType) -> Option<&str>`
- `Op::SetStepVia { tree, node, via: Option<ItemRef>, provenance }`, `Op::SetStepAttackType { tree, node, attack_type: Option<AttackType>, provenance }`
- `AttackTree::idx_of(&NodeId) -> Option<NodeIdx>`, `AttackTree::get(NodeIdx) -> Option<&Node>`, `Node::gate_kind() -> Option<GateKind>` (`None` for a step)
