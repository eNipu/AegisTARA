## The format (implement exactly this)

A line is `<indent><prefix><name><tail>`. The tail is zero, one or two segments, each written
` | key: value`.

Reading the tail of one line, after the prefix (`OR `, `AND `, `SEQ `, `- `) is removed and the
rest is trimmed. Call the rest `rest`:

1. Repeat while fewer than two values have been taken:
   - Find the last ` | ` (space, pipe, space) in `rest` (`rfind`). None: stop.
   - `seg` = the text after it, trimmed. `seg` is a *candidate* when it contains `:` and the part
     before the first `:` is not empty and is only ASCII lower-case letters `a` to `z`.
   - Not a candidate: stop. The segment is part of the name.
   - Candidate with key `through` or `type` whose value (the part after the first `:`, trimmed) is
     not empty and whose key was not taken yet on this line: take it, and set
     `rest = rest[..pos].trim_end()`.
   - Candidate with key `through` or `type` already taken on this line: `Err(OutlineError::DuplicateNote(line))`.
   - Any other candidate (another key, or an empty value): `Err(OutlineError::UnknownNote(line))`.
2. What is left of `rest` is the name. Once both `through` and `type` are taken, stop without
   looking further left: everything left is the name, even if it looks like a candidate.
3. A value of `-` means none (`None`). Any other value is kept as written (trimmed).
4. The existing checks then run on the name: empty gives `NoText(line)`, more than
   `MAX_LABEL_CHARS` characters gives `LabelTooLong(line)`.

Examples (name, through, type):
- `Flash | through: C00 | type: debug-access` gives (`Flash`, `C00`, `debug-access`)
- `Flash | type: debug-access | through: IF03` gives (`Flash`, `IF03`, `debug-access`)
- `Flash | through: -` gives (`Flash`, none, none), and the line counts as having a tail
- `Read A | B` gives (`Read A | B`, none, none)
- `Ratio | Then: go` gives the whole text as the name (`Then` has an upper-case letter)
- `A | note: x | through: - | type: -` gives (`A | note: x`, none, none)
- `A | note: x` gives `UnknownNote`
- `A | throgh: C00` gives `UnknownNote`; `A | through:` gives `UnknownNote`
- `A | type: a | type: b` gives `DuplicateNote`

Rules across lines, in `parse_outline_annotated`:
- A gate line (first occurrence or later) whose `through` or `type` is `Some` gives
  `Err(OutlineError::NoteOnGate(line))`. A gate with `-` values is fine.
- A step's values come from its first line. A later line with the same name (a shared step) is
  fine when it has no tail at all or when its two values equal the first line's; otherwise
  `Err(OutlineError::NoteConflict(line))`. The first line of the outline (the root) follows the
  same rules as any other first line.

Writing one line: the tail for a node with values `(through, attack_type)`:
- If the name alone, read by the rules above, would not come back as the same name with no values
  (it returns an error, or a shorter name), write both segments, `-` for none:
  ` | through: <v or -> | type: <v or ->`. This applies to gates too (always `-`).
- Otherwise write ` | through: <v>` if `through` is `Some`, then ` | type: <v>` if `attack_type`
  is `Some`, and nothing for `None`.
- The same tail is written on every line of a shared node.
