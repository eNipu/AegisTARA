## Problem & Goal
Goals and claims today say *what* is required but not *who* is responsible, so a supplier's TARA cannot say "Customer" without hard-coding a name. Consultants and their customer's reviewers need the party of each goal and claim, and a "share" treatment is meaningless unless another party takes the risk (FND-08). After this job the model has a typed `Party` list with a stable `P` visual ID, goals and claims carry a sorted, capped `responsible` list, the relation registry and tables expose it to the client-level picker, the linter warns on a share with no other party, and Excel import/export round-trips a Responsible column. Business value (P7): the new type earns its ops, snapshot fields and registry rows by serving the goals page, the lint and the Excel exchange from one model, rather than three per-page hacks; no new screen code is added (owner rule 2026-11-11).

## Decisions
- **Dedicated typed arena, not a generic-store row.** ADR 0068 lists parties as a future `ElementKind` row, but the feature requires `Party { name, kind }` and `Vec<PartyIdx>`, recipe row 1 requires a typed index, and the lint needs a statically known `kind` to decide "other than Us"; a string attribute would make that rule untypeable. `party.rs`, `PartyId`, `PartyIdx`, `VisualPrefix::Party` (`"P"`).
- **`responsible` is added by link/unlink ops, not as a required field of `AddCybersecurityGoal`/`AddCybersecurityClaim`.** Those `Add` ops have dozens of doc-test and fixture call sites (L24); a separate pair of ops keeps the op log additive and the inverse exact. The structs still store `Vec<PartyIdx>` (sorted by PartyId, unique).
- **`PartyKind` is a real enum** (`Us | Customer | Supplier | Other`) with `as_str`/`from_str`, not a free-text attribute; the lint and Excel mapping need the closed set.
- **Caps are new distinct constants:** `MAX_PARTIES = 256`, `MAX_RESPONSIBLE = 16`. Do not alias `MAX_GOAL_CONTROLS`; check the existing cap exists before referencing it (L08).
- **Removal guard (L04, recipe row 2):** `RemoveParty` is refused while any goal or claim lists it (`PartyInUse { party, goals, claims }`); the client clears responsible links first in one undo step. The inverse of `RemoveParty` stays a plain `AddParty`.
- **Lint:** one new `LintCode::ShareTreatmentWithoutOtherParty { threat }` at `Warning`. It fires only when the threat's treatment is `Share` and its linked claim names zero parties whose kind is not `Us`. A share with no claim already fires the existing `RetainOrShareTreatmentWithoutClaim`; one warning per threat, not per party.
- **Persistence is additive:** `parties` and `responsible` snapshot fields are omitted when empty, so a v1 fixture with no parties saves identical bytes and loads unchanged; decode caps reject over-long/over-cap input with a `Limit` variant.
- **Client scope is data only:** no `.slint`, no `aegis-shell`, no screenshots (owner rule 2026-11-11, L11). The GPUI workbench renders the picker and link column later.
- **Fluent ids use hyphens** (L27). No stored format outside the additive snapshot/op-log fields, no security, licensing, crypto, `unsafe`, dependency or user-data deletion.
- **Review-mandated `Project::eq` fixes grew slice 145b past its cap:** a `same_goal` responsible comparison and a slot-order-independent `same_claim` comparison, each with a test, made the honest diff 503 counted lines against 480. The cap was raised to 540 rather than compressing the code.

## Acceptance Criteria
1. `aegis-model` exports `Party`, `PartyKind`, `PartyId`, `PartyIdx`, `MAX_PARTIES`, `MAX_RESPONSIBLE`, `VisualPrefix::Party` (`"P"`) and a `Project::parties()` arena accessor; `VisualPrefix::Party.format(0) == "P00"` and `.format(100) == "P100"`. Check: `cargo test --locked -p aegis-model --lib id`.
2. Ops `AddParty`, `RenameParty`, `SetPartyKind`, `RemoveParty`, `LinkGoalParty`, `UnlinkGoalParty`, `LinkClaimParty`, `UnlinkClaimParty` each have an exact inverse documented in the `op.rs` table; applying an op then its inverse restores the project (compared with `save()` bytes, L06). Check: `cargo test --locked -p aegis-model --test parties` and `cargo test --locked -p aegis-client --test undo_every_op`.
3. Guards, each with a test that only that guard refuses and that checks the error variant (L09): duplicate/unknown party id, blank/over-long name, `MAX_PARTIES` full, duplicate/unknown/unsupported party kind on a link, `MAX_RESPONSIBLE` full, unlinking a party not listed, removing a party that a goal or claim lists (`PartyInUse`), and over-cap decode input. Error text never contains a party name.
4. `CybersecurityGoal::responsible()` and `CybersecurityClaim::responsible()` return `&[PartyIdx]` sorted by PartyId and unique; every construction site still compiles because `Add` ops are unchanged. Check: `cargo test --locked -p aegis-model --test parties`.
5. Op log: all eight new ops write and read back equal (`OpLogWriter`/`OpLogReader`); unknown kind/party keys are refused with the right `VocabKind`; over-long names and over-cap lists are refused by the decoder. Check: `cargo test --locked -p aegis-model --test store`.
6. Snapshot: a project with parties and responsible links saves a `parties` object and `responsible` fields, loads back with equal `save()` bytes; a project without them saves the bytes it saves today, and `tests/fixtures/project-v1.json` loads unchanged. Decode caps have just-under and just-over tests. Check: `cargo test --locked -p aegis-model --test store` and `--test store_limits`.
7. Property tests cover all eight new ops (random generator, `ops_properties`, `store_properties`) and still pass. Check: `cargo test --locked -p aegis-model --test ops_properties --test store_properties`.
8. `ProjectDiff::parties()` lists added/removed/modified `PartyId`s in canonical order and is counted by `is_empty()`; party and responsible changes add no risk delta. Check: `cargo test --locked -p aegis-model --test parties`.
9. `LintCode::ShareTreatmentWithoutOtherParty` is `Warning` and fires exactly for `Share` with a linked claim naming zero non-Us parties; tests cover share+only Us, share+other party, share+no claim, retain+no party, reduce, and a claim with no parties — only the first fires this code. Check: `cargo test --locked -p aegis-model --test party_lint`.
10. `relations.rs` has one row per new link (`GOAL_RESPONSIBLE`, `CLAIM_RESPONSIBLE`) with `from`/`to` `ElementKind::{Goal,Claim} → Party`, `many = true`, a unique hyphenated Fluent label in en/ja/pseudo, a `read` and typed `link`/`unlink` returning `Edit::LinkGoalParty`/`Edit::LinkClaimParty`; `elements_of_kind` covers `Party`. Check: `cargo test --locked -p aegis-client --test relations` and `--test table_conventions`.
11. The goals and claims table rows carry a Responsible link column (`ColumnKind::Links`), and `pages::goal_rows`/`claim_rows` expose the responsible parties; `table.rs` renders their visual IDs and names. Check: `cargo test --locked -p aegis-client --test table_conventions`.
12. `commands.rs` has typed `Edit`s for goal and claim responsible links whose `to_ops` yields exactly one `Op` each, applied-then-undone restores the project, and `undo_label.rs` names them. Check: `cargo test --locked -p aegis-client --test undo_every_op`.
13. `report/xlsx.rs` exports a `Parties` sheet and a Responsible column on the Goals and Claims sheets with the formula guard; `report/doc.rs` carries Responsible in the goal/claim tables; `excel.rs` auto-detects an English `Responsible` / Japanese `責任者` column and maps it to responsible links on the goal or claim in that row. Check: `cargo test --locked -p aegis-client --test excel` and `--test xlsx`.
14. en, ja and pseudo catalogs resolve `responsible`, the two relation labels and the four party-kind labels; no `.slint`/`aegis-shell` file changes; `cargo fmt --all` and `scripts/ci.sh` pass with no new dependency.
