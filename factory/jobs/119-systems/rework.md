## Answers

1. Owner rule (standing): no new Slint screen work; all future UI is built in GPUI, which is not on master yet. Plan the model (ops, inverses, store, diff, derived system of interfaces, assets, threats and trees, the lint), the client side (the batches for remove and bulk "Move to system", the Systems table rows and draft row data, the picker data, the view filter as per-user settings that is never an op, and the filtered page data) and all tests at the model and client level. Do not plan any change to `.slint` files or to Slint-only glue in `aegis-shell`; where the backlog line asks for a headless keyboard test at 900 px, test the client's view switch instead. List the screen part in the spec as left for the GPUI shell.

2. Read `docs/adr/0068-generic-element-store.md` before choosing the storage. A system changes no computed number. Decide in the spec whether it is a kind in the generic element store or a typed arena as the backlog line says, and give the reason in two or three sentences (for example: a component must point at its system, and generic elements link only to threat scenarios today). Choose the smaller change that keeps the property tests in the backlog line possible.
