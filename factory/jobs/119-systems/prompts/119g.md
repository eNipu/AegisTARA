## Goal
A user looks at one system, a chosen subset, or all of them. This slice adds the view as a value, the data for its menu (each system with its component count), the text of the chip in the top bar, the command palette entries, and a place in the settings file that remembers the view per user and project. The view is a display choice: it is never an op and is never stored in the project. Slice 119h applies the view to the pages; the screen is built later in the GPUI shell.

Facts about what exists:
- Model: `project.elements(ElementKind::System)` yields `(ElementId, &Element)` in ID order, `Element::name()`; `project.element(id)` with `kind()`; `project.component_system(ComponentIdx) -> Option<ElementId>` (through the top-level ancestor); `project.components()` yields `(ComponentIdx, ComponentId, &Component)`; `project.component_count()`. At most 64 systems (`aegis_model::MAX_SYSTEMS`).
- Client: `crates/aegis-client/src/systems.rs` (slice 119f) holds `SystemRow`, `system_rows`, `system_choices`, `system_name`.
- An `ElementId` prints as a UUID with `to_string()` and parses with `text.parse::<ElementId>()` (see `crates/aegis-client/src/view.rs` lines 513-535 for the same pattern on other IDs).

   ```rust
   /// Which systems the user looks at. Empty means all systems.
   #[derive(Clone, Debug, Default, PartialEq, Eq)]
   pub struct SystemView(BTreeSet<ElementId>);
   impl SystemView {
       pub fn all() -> Self
       pub fn only(id: ElementId) -> Self
       pub fn of(ids: impl IntoIterator<Item = ElementId>) -> Self
       pub fn is_all(&self) -> bool
       pub fn contains(&self, id: ElementId) -> bool
       pub fn systems(&self) -> impl Iterator<Item = ElementId> + '_   // ID order
       /// Checks or unchecks one system. Unchecking the last one gives all systems.
       pub fn toggled(&self, id: ElementId) -> Self
       /// Drops every ID that is not a live system of `project`.
       pub fn normalized(&self, project: &Project) -> Self
   }
   ```
2. `systems.rs`, the menu:
   ```rust
   pub struct ViewChoice { pub id: ElementId, pub name: String, pub components: usize, pub checked: bool }
   pub struct ViewMenu {
       /// "All systems", "Brake", "Brake + ADAS", "Brake +2".
       pub chip: String,
       /// For a narrow window: "All systems", "Brake", "Brake +1".
       pub chip_short: String,
       /// True when the view is all systems (the radio at the top).
       pub all: bool,
       /// Every component of the project.
       pub total: usize,
       /// One per system, in ID order.
       pub choices: Vec<ViewChoice>,
       /// Components in no system.
       pub unassigned: usize,
   }
   pub fn view_menu(project: &Project, view: &SystemView) -> Option<ViewMenu>
   ```
   `view_menu` returns `None` when the project has no systems. It normalizes the view first. `components` counts every component whose `component_system` is that system, children included, so the choices and `unassigned` add up to `total`. Chip rules, with the checked systems in ID order: none checked gives "All systems"; one gives its name; two give "A + B"; three or more give "A +N" where N is the number of others. `chip_short` is the name for one and "A +N" for more. Time O(components x depth + systems).
3. `systems.rs`, the command palette entries:
   ```rust
   pub struct ViewCommand { pub label: String, pub view: SystemView }
   pub fn view_commands(project: &Project, view: &SystemView) -> Vec<ViewCommand>
   ```
   Empty when the project has no systems. Otherwise: "View: All systems" (`SystemView::all()`); for each system "View: {name}" (`only`); and, when the view is not all, for each system not in it "View: add {name}" (the view plus that system). Order: all, then the "View: {name}" entries in ID order, then the "add" entries in ID order.
4. `settings.rs`:
   ```rust
   /// Most projects whose view is remembered; the oldest is dropped first.
   pub const MAX_REMEMBERED_VIEWS: usize = 16;
   #[derive(Clone, Debug, Default, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
   #[serde(default)]
   pub struct SystemViewSetting {
       /// `Settings::view_key(user, project)`.
       pub key: String,
       /// System IDs, as text.
       pub systems: Vec<String>,
   }
   ```
   `Settings` gets `pub system_views: Vec<SystemViewSetting>` ("The systems each user looks at in each project (SYS-03); never part of a project."). Methods:
   - `pub fn view_key(user: &str, project: &str) -> String`: `format!("{user}\n{project}")`. `project` is the server address plus the project ID, or the folder path in standalone mode; the caller chooses.
   - `pub fn system_view(&self, key: &str) -> SystemView`: the remembered view, or all. Text that is not a valid ID is skipped; at most `MAX_SYSTEMS` IDs are read.
   - `pub fn set_system_view(&mut self, key: &str, view: &SystemView)`: removes the entry for `key`; if the view is not all, appends a new entry at the end; then drops entries from the front while there are more than `MAX_REMEMBERED_VIEWS`.
   With 16 entries of 64 IDs the list is about 40 KB, inside `MAX_SETTINGS_BYTES` (64 KB); say this in the doc comment of the constant.
