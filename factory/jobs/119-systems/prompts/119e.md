# Build prompt: 119e Edits for systems: add, rename, remove, move to system

You are implementing one small change in the AegisTARA repository (Rust workspace).
Work only inside `factory/worktrees/119-systems/`, on branch `factory/119-systems`.

## Goal
The client can state every system change as one `Edit`, which becomes one batch of ops and one undo step: add, rename and remove a system, and move one or several components to a system or out of one. Removing a system first takes its components out, so nothing else is lost and undo brings everything back. The undo label says what happened in words.

Facts about the model (already built):
- A system is a generic element: `Op::AddElement { id: ElementId, kind: ElementKind::System, name, provenance }`, `Op::RenameElement { id, name, provenance }`, `Op::RemoveElement { id }`. `project.element(id) -> Option<&Element>` with `kind()`, `name()`, `attributes()`; `project.elements(ElementKind::System)` yields `(ElementId, &Element)`.
- `Op::SetComponentSystem { id: ComponentId, system: Option<ElementId>, provenance }` sets the system of a top-level component. `Component::system() -> Option<ElementId>`, `Component::parent() -> Option<ComponentIdx>`.
- The model refuses: a system on a component that has a parent; `SetComponentParent` with `Some` parent while the component has a system; `RemoveComponent` while the component has a system; `RemoveElement` on a system while a component is in it or while it has attributes.
